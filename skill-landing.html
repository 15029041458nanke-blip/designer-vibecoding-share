两条开发路径

01

无设计稿

Zero to One

从一个产品想法出发，不需要任何设计资产。脚手架自动配置从意图到 PRD 到 handoff 的全链路模板。

  • ①明确产品意图与目标用户
  • ②填写 active-prd.md，拆分首个 PRD 切片
  • ③写 todo.md，创建第一份 handoff.json
  • ④运行 npm run agent:run

02

有设计稿

Design Driven

以 Figma 设计稿为输入源，自动生成设计分析、设计合约、Design QA 四份核心文件，驱动整个开发流程。

  • ①填写 docs/design/figma-source.md
  • ②完成 design-analysis.md 与 design-contract.md
  • ③按设计合约驱动 PRD 与开发
  • ④开发完成后运行 design-qa.md 校验

三条协作链路

选择你的
AI 协作方式

A

多模型协作

Claude + Codex

Claude 负责长上下文规划与任务拆解，Codex 专注执行。适合复杂任务、长会话场景。

  • Claude 配额充足时优先
  • 任务复杂、上下文长
  • 希望规划与执行分离

B

单模型多角色

Codex 全流程

一个模型独立扮演 PM、架构师、工程师、测试、reviewer 五个角色，一个环境跑完全部流程。

  • 想在一个环境里完成全部
  • Claude 配额用尽时切换
  • 适合独立开发者场景

C

OpenClaw 后台

叠加层 · 可选

C 不替代 A/B，而是在其上叠加后台执行能力。任务挂起后台跑，不用一直盯着窗口。

  • 需要远程或后台工作
  • 通过 Git 触发任务执行
  • 配合 A 或 B 同时使用

使用方式

只问 4 个
关键问题

告诉 Claude 这 4 个答案，脚手架自动生成，不需要手动创建任何文件。Claude 会弹出 UI 对话框逐项引导。

1

目标目录或项目名称

可以是路径，也可以只说项目名

2

是否已有设计稿？

有 → design-driven，没有 → zero-to-one

3

默认协作模式

多模型协作 还是 单模型多角色

4

是否启用 OpenClaw？

需要后台执行时才选 yes

terminal 
# Claude 自动生成并运行

python3 scripts/init_designer_vibecoding_project.py \
  --target    "~/projects/my-app" \
  --project-name "my-app" \
  --path-mode design-driven \
  --workflow  claude-planner-codex-builder \
  --openclaw

# 初始化完成后开始工作

npm run workflow:intent  # 中文切换协作模式
npm run agent:run        # 执行当前 handoff
npm run openclaw:daemon  # 开启后台守护

中文意图切换

直接说"切换到多模型协作"或"开启 OpenClaw 后台执行"，脚本会自动识别意图并更新协作模式。

初始化后你会拿到什么

这些不是空模板——每个文件开箱即用，打开就能开始填写第一轮任务。

📋

AGENTS.md

项目协作规则入口，定义工作流、角色约束与完成定义

🔀

current-workflow.md

当前激活的协作模式，是唯一的工作流状态源

📦

handoff.json

单一任务交接源，填写后即可运行 agent_run.sh

📡

status.json

实时执行状态：idle / running / done / failed

🎯

active-sprint.md

当前冲刺目标、检查清单与进度追踪

✅

todo.md

当前执行计划，按路径模式预填路径相关 checklist

🔧

agent_run.sh

单一执行入口，填写执行命令后即可通过 npm 触发

🌐

workflow_intent.sh

中文意图识别，自动更新 current-workflow.md
