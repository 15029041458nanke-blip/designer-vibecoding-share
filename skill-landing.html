两条开发路径

01

无设计稿

Zero to One

从一个产品想法出发，不需要任何设计资产。脚手架自动配置从意图到 PRD 到 handoff 的全链路模板。

  • ①明确产品意图与目标用户
  • ②填写 active-prd.md，拆分首个 PRD 切片
  • ③写 todo.md，创建第一份 handoff.json
  • ④运行 npm run agent:run

02

有设计稿

Design Driven

以 Figma 设计稿为输入源，由 design-analyst 角色先做设计转译，产出设计驱动 PRD 与设计合约，再驱动开发与 Design QA 闭环。

  • ①design-analyst 分析 Figma，产出 design-analysis.md + design-contract.md
  • ②product-strategist / project-manager 校验范围，形成最终 PRD
  • ③architect 定义边界，engineer + tester 按 handoff 实施验证
  • ④design-analyst 执行 Design QA，确认实现与设计一致

三条协作链路

完整角色团队
双模型分工

A

多模型协作

Claude + Codex

两条链路共享同一套完整角色团队。链路 A 中，Claude 主导规划侧全部角色，Codex 主导执行侧角色。

  • Claude 侧：design-analyst · product-strategist · project-manager · architect · reviewer
  • Codex 侧：engineer · tester
  • 适合复杂任务、上下文长、需规划与执行分离的场景

B

单模型多角色

Codex 全流程

链路 B 同样使用完整角色团队，由 Codex 一个模型依次驱动所有角色，在单个环境跑完全部流程。

  • Codex 串联：PM · architect · engineer · tester · reviewer
  • Claude 配额用尽或想在一个环境完成全部时选用
  • 适合独立开发者、快速迭代场景

C

OpenClaw 后台

叠加层 · 可选

C 不替代 A/B，而是在其上叠加后台执行能力。Worker 轮询 GitHub handoff，执行后自动推回结果——不用一直盯着窗口。

  • 前置：git init + push 到 GitHub、安装 jq、配置 SSH/Token 免交互凭据
  • 初始化后脚手架会输出完整 6 步 git 配置清单
  • 支持演练模式：OPENCLAW_DRY_RUN=true npm run openclaw:worker
  • 配合 A 或 B 同时使用，三条链路不互斥

Design Analyst · 实战案例

从 Figma 到代码的
精准还原体系

在 vibcoding 思维导图项目中，多轮 Figma → 代码还原与质检，将发现的 6 类典型根因系统化为 7 条强制规则，落地为团队共同维护的 design-role-rules.md——第一稿还原率从约 60% 提升至 80%+。

7 还原规则类别
6 典型根因归档
80% 第一稿还原率目标

强制规则体系

7 类还原规则 — 每类均有根因与真实案例支撑

1

图标规则

Figma IMAGE-SVG 节点无法通过 MCP 导出路径数据。统一用 IconPlaceholder 占位，禁止用文字替代或自行绘制语义化图标。

型号固定：20px 容器 · 18px 圆 · 1.5px stroke
2

Border 规则

Figma Inside stroke 不压缩 fill 子内容；CSS border-box 会真实压缩。含 fill 子元素的结构性容器，边框必须用 outline，不用 border。

验证：渲染尺寸 == Figma 标注尺寸
3

尺寸规则

sizing 类型（hug / fixed / fill）必须从组件自身 Component Set 的 layout token 直接读取，禁止从使用侧实例推断。

sizing → componentSetId → layout_xxx.sizing
4

节点类型识别

实现任何内容前，先查 Figma 节点 type 字段。TEXT 才可用文字；IMAGE-SVG / VECTOR / BOOLEAN_OPERATION 一律用 IconPlaceholder。

未查 type → 凭语义猜 → 自造内容
5

布局对齐规则

MCP 对 Auto Layout 元素直接返回 alignItems / justifyContent；绝对定位元素只返回 locationRelativeToParent: {x, y}——需手动判断居中意图。

x == (父-子)/2 → inset:0 + flex，禁止字面翻译坐标
6

组件系统规则

变体必须从 Component Set 顶层节点枚举，不能从使用侧嵌套实例读取。使用侧只展示当前被用到的变体，可能遗漏其余变体。

正确路径：componentSetId → children → 完整变体
7

QA 走查清单

逐层验证：图标（无文字替代）→ 尺寸（±0.5px）→ Border（渲染尺寸一致 / fill容器用outline）→ 布局（行列数量 / 绝对定位居中判断）→ 变体（Component Set 完整覆盖）→ Token（颜色变量绑定）。

每实现一个组件，必须按顺序过一遍此清单

还原前 vs 还原后

菜单组件的 5 个典型修复

以下问题均来自 vibcoding 思维导图菜单组件（menu atom）的真实质检过程，每一项都在规则手册中留有案例记录。

§5 布局对齐 ColorDot
check 图标偏移 Figma x:6 y:6 = (28-16)/2 居中值，字面翻译后 border:2px 使坐标原点偏移 2px
❌ 还原前
.color-dot__check {
  position: absolute;
  top: 6px;
  left: 6px;
}

→ 图标实际距外边 8px，视觉偏上偏左 2px

✓ 还原后
.color-dot__check {
  position: absolute;
  inset: 0;
  display: flex;
  align-items: center;
  justify-content: center;
}

→ 居中意图 → 用 flex 对齐，与 border 无关

§2 Border 规则 颜色面板
5 列 → 4 列 Figma Inside stroke 不压缩 fill 子内容，CSS border-box 真实压缩内容区，208px → 207px，装不下第 5 个圆点
❌ 还原前
.dropdown {
  width: 208px;
  border: 0.5px solid rgba(0,0,0,0.08);
  box-sizing: border-box;
  /* 内容区 207px */
}

→ 5×28px + 4×11px = 184px > 183px，只排 4 列

✓ 还原后
.dropdown {
  width: 208px;
  outline: 0.5px solid rgba(0,0,0,0.08);
  border: none;
  /* 内容区 208px */
}

→ outline 不参与盒模型，5 列正常排布

§3 尺寸规则 FocusBtn
宽度错误 从使用侧父容器推断 sizing = fill，未直接查 FocusBtn Component Set
❌ 还原前
.focus-btn {
  width: 100%; /* fill? */
  height: 36px;
}

→ 从使用侧推断 fill，实际 Figma 是 fixed

✓ 还原后
.focus-btn {
  width: 40px; /* fixed */
  height: 36px;
}

→ 查 Component Set 5018:73659 → sizing: fixed, 40×36

§4 节点类型 BorderColorPanel
线型图标用文字 未查 Figma 节点 type，凭业务语义（实线/虚线/点线）自造文字内容
❌ 还原前
// 自造文字按钮
实线
虚线
点线

→ Figma 节点 5023:57260 实际 type = IMAGE-SVG

✓ 还原后
// 图标占位
  icon={}
  aria-label="实线"
/>

→ 查节点 type 后改为 IconPlaceholder

§6 组件系统 ColorDot
漏掉 hover 变体 从使用侧父 Frame 下嵌套实例读取变体，使用侧只展示了部分变体，遗漏 hover
❌ 还原前（只有 2 变体）
type Variant =
  'default' | 'selected'

// hover 变体遗漏

→ 从 5005:29748 使用侧读取，仅见 2 个状态

✓ 还原后（完整 6 变体）
type Variant =
  'default' | 'hover' | 'selected'

// 查 5023:54209 Component Set
// → 3态 × empty(T/F) = 6 变体

→ componentSetId 顶层 children 枚举完整变体

使用方式

只问 4 个
关键问题

告诉 Claude 这 4 个答案，脚手架自动生成，不需要手动创建任何文件。Claude 会弹出 UI 对话框逐项引导。

1

目标目录或项目名称

可以是路径，也可以只说项目名

2

是否已有设计稿？

有 → design-driven，没有 → zero-to-one

3

默认协作模式

多模型协作 还是 单模型多角色

4

是否启用 OpenClaw？

需要后台/远程执行时选 yes — 需要 GitHub 仓库 + jq + 免交互 Git 凭据；脚手架会在完成后输出 6 步配置清单

terminal 
# Claude 自动生成并运行

python3 scripts/init_designer_vibecoding_project.py \
  --target    "~/projects/my-app" \
  --project-name "my-app" \
  --path-mode design-driven \
  --workflow  claude-planner-codex-builder \
  --openclaw

# 初始化完成后开始工作

npm run workflow:intent  # 中文切换协作模式
npm run agent:run        # 执行当前 handoff
npm run openclaw:daemon  # 开启后台守护

中文意图切换

直接说"切换到多模型协作"或"开启 OpenClaw 后台执行"，脚本会自动识别意图并更新协作模式。
