06

真正让项目不跑偏的，不是 prompt，而是工作习惯

这页我不想只讲抽象原则，而是直接讲这套习惯具体怎么落到项目里。

Plan

复杂任务先进 Plan

超过 3 步、涉及架构判断，就先写 spec、范围、验收和风险。

Subagents

研究和并行分析拆出去

让主上下文只保留当前决策，避免一个窗口里塞满所有细节。

Lessons

每次纠正都写进 lessons

把反复出现的错误变成默认规则，而不是每次重新提醒。

Verify

完成前必须留下证据

测试、日志、diff、行为对比，至少要证明这件事真的跑通了。

Agent 配置文件（可直接复制） 
工作流编排（Workflow Orchestration）
1. 默认进入 Plan 模式
- 任何非简单任务（3 步以上或涉及架构决策）都进入 plan 模式
- 一旦出现偏差，立刻停止并重新规划
- plan 模式不仅用于搭建，也用于验证步骤
- 先写详细规格说明（spec）降低歧义

2. 子代理策略（Subagent Strategy）
- 大量使用子代理，让主上下文窗口保持干净
- 研究、探索和并行分析交给子代理处理
- 面对复杂问题，用子代理堆算力
- 每个子代理只负责一条思路

3. 自我改进闭环（Self-Improvement Loop）
- 用户每次纠正后：写入 tasks/lessons.md
- 给自己写规则，避免同类错误再次发生
- 持续迭代这些经验，直到错误率下降
- 每次会话开始时，先回顾 lessons

4. 完成前必须验证（Verification Before Done）
- 没有证明能跑通，就不要标记任务完成
- 必要时对比主分支与修改后的行为差异（diff）
- 自问：一个 Staff Engineer 会认可吗？
- 跑测试、查日志、给出可验证证据

5. 追求优雅（Demand Elegance）
- 对非简单改动：先问有没有更优雅的方式
- 如果修复很 hack：问基于现在认知应该怎么做才优雅
- 对简单显然的修复不必过度设计
- 对外呈现前先挑战自己的实现方案

6. 自主修 Bug（Autonomous Bug Fixing）
- 收到 bug 报告：直接修，不要让用户手把手带
- 指向日志、错误信息、失败测试，然后解决它
- 不要求用户做额外上下文切换
- 不用别人告诉你怎么做，也能把 CI 挂掉的测试修好

任务管理（Task Management）
- 先写计划：把 plan 写到 tasks/todo.md，用可勾选清单列出
- 验证计划：开始实现前先确认/对齐计划
- 跟踪进度：做一项勾一项
- 解释改动：每一步给出高层概述
- 记录结果：在 tasks/todo.md 增加 review 小节
- 沉淀经验：用户纠正后更新 tasks/lessons.md

07

加入 design-analyst 之后，PRD 变得完全不一样

这页不讲抽象原则，直接看加入设计分析角色前后，需求描述长什么样。

没有 design-analyst 时
PRD 节选

目标：
实现首页导航区域

需求：
- 页面风格和 Figma 保持一致
- 顶部有搜索、切换按钮和操作区
- 卡片要有 hover 状态
- 颜色和间距尽量还原

问题：
- 哪些是组件，哪些只是视觉相似，没写清楚
- 状态只有 hover，没有 disabled / loading
- spacing、颜色、字号没有 token 映射
- 工程拿到后仍然要自己猜
加入 design-analyst 后
PRD 节选

模块：Header / Toolbar

组件映射：
- SearchInput → 使用 Input/Search 组件
- ViewSwitch → SegmentedControl，2 个状态：map / document
- PrimaryAction → Button/Primary

设计约束：
- 间距：gap-16 / padding-x-24
- 字体：title-sm / body-sm
- 颜色：surface-default / text-primary / border-subtle
- 状态：default / hover / active / disabled / loading

验收：
- 所有颜色与间距必须走 tokens
- 图标尺寸固定 20px
- Header 高度 72px，不允许自由漂移
设计稿不是直接交给开发，而是先被翻译成：组件映射 + token 约束 + 状态定义 + 验收标准。

三条模式混着用，怎么保证不乱

真实使用里，用户可能上午还在 Claude Code + Codex，下午 tokens 用光切到 Codex 多 agent，晚上回家再用 OpenClaw 远程继续跑。关键是无缝衔接，不丢上下文。

上午

Claude + Codex

用 Claude 管上下文，Codex 执行。

下午

Claude tokens 用光

切到 Codex 多 agent，继续沿当前任务推进。

晚上

回家继续做

用 OpenClaw 后台拉 handoff，继续执行。

结果

无缝衔接

任务线不断，状态线不断，上下文线也不断。
